VKM Architecture Reference

The Virtual Kitchen Machine is an automated culinary execution processor executing deterministic timed operations.

  • LOAD_VESSEL <DISH>: Mounts automated bowl.
  • DISPENSE <ING>, <QTY>, <UNIT>: Engages ingredient dispenser feeder.
  • STIR <RPM>, <SEC>: Sets mechanical whisk/stirrer rate.
  • HEAT_BOIL <TEMP_C>, <SEC>: Engages induction boiling plate.
  • HEAT_BAKE <TEMP_C>, <SEC>: Regulates convection oven heat.
  • HEAT_FRY <TEMP_C>, <SEC>: Regulates griddle frying surface.
  • PLATING_SERVE: Discharges finished dish to plating station.
  • HALT: Terminates processor execution.

Digital Cookbook — Language & Compiler Specification

1. Formal EBNF Grammar

program         ::= recipe_decl statement_list serve_stmt EOF ;
recipe_decl     ::= "RECIPE" identifier ";" ;
statement_list  ::= { statement } ;
statement       ::= add_stmt | timed_stmt | chop_stmt ;
add_stmt        ::= "ADD" "(" number "," unit "," identifier ")" ";" ;
timed_stmt      ::= timed_op "(" number "," time_unit ")" ";" ;
timed_op        ::= "MIX" | "BOIL" | "BAKE" | "FRY" | "SIMMER" | "CHILL" | "WHISK" | "REST" ;
chop_stmt       ::= "CHOP" "(" identifier ")" ";" ;
serve_stmt      ::= "SERVE" ";" ;
unit            ::= "CUP" | "TBSP" | "TSP" | "GRAM" | "KG" | "ML" | "LITER" | "PIECE" | "PINCH" ;
time_unit       ::= "SECONDS" | "MINUTES" | "HOURS" ;

2. Supported Dishes & Requirements

  • PANCAKE: Requires FLOUR, MILK, EGG. Supports FRY, MIX, WHISK.
  • SPONGE_CAKE: Requires FLOUR, SUGAR, EGG, BUTTER. Supports BAKE, MIX.
  • PASTA: Requires PASTA, WATER, SALT. Supports BOIL, FRY, MIX.
  • HERBAL_TEA: Requires WATER, TEA_LEAVES. Supports BOIL, SIMMER.
  • FRENCH_OMELETTE: Requires EGG, BUTTER, SALT. Supports FRY, WHISK.
  • FRESH_SALAD: Requires LETTUCE, TOMATO, OIL. Supports CHOP, MIX, CHILL.

3. Optimization Passes

  1. Unit Normalization: Converts volume to ML, mass to GRAM, and durations to SECONDS.
  2. Adjacent Instruction Merging: Combines contiguous additions of identical ingredients and contiguous timed actions.
  3. Dead Code Elimination: Prunes zero-quantity and zero-duration operations.
