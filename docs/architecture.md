# Digital Cookbook Compiler — System Architecture

## 1. Architectural Philosophy
The **Digital Cookbook Compiler** is built on classic compiler design principles, featuring a deterministic, decoupled 6-phase pipeline. Unlike trivial interpreters or LLM-backed mock generators, every token, parse tree node, symbol record, intermediate instruction, optimization transformation, and target assembly instruction is generated by hand-written compiler algorithms.

---

## 2. Compiler Pipeline Architecture

```
                                  +----------------------+
                                  |  Cookbook DSL Source |
                                  +----------------------+
                                             |
                                             v
                           +-----------------------------------+
                           |  PHASE 1: LEXICAL ANALYSIS        |
                           |  (Hand-written Character Scanner) |
                           +-----------------------------------+
                                             |  Token Stream + Coordinates
                                             v
                           +-----------------------------------+
                           |  PHASE 2: SYNTAX ANALYSIS         |
                           |  (Recursive-Descent Parser)       |
                           +-----------------------------------+
                                             |  Abstract Syntax Tree (AST)
                                             v
                           +-----------------------------------+
                           |  PHASE 3: SEMANTIC ANALYSIS       |
                           |  (Domain Knowledge & Symbol Table)|
                           +-----------------------------------+
                                             |  Verified AST + Symbol Table
                                             v
                           +-----------------------------------+
                           |  PHASE 4: IR GENERATION           |
                           |  (Three-Address Code IR)          |
                           +-----------------------------------+
                                             |  Linear 3AC Instructions
                                             v
                           +-----------------------------------+
                           |  PHASE 5: CODE OPTIMIZATION       |
                           |  (Multi-pass Peephole & Canonical)|
                           +-----------------------------------+
                                             |  Optimized 3AC IR
                                             v
                           +-----------------------------------+
                           |  PHASE 6: TARGET CODE GENERATION  |
                           |  (Virtual Kitchen Machine Bytecode)|
                           +-----------------------------------+
                                             |
                                             v
                           +-----------------------------------+
                           |  JSON REST API / INTERACTIVE IDE  |
                           +-----------------------------------+
```

## 3. Module Breakdown & Responsibilities

| Module | File | Phase | Primary Responsibilities |
|---|---|---|---|
| **Tokens & Types** | `compiler/tokens.py` | Infrastructure | Defines token enumerations, keyword maps, and data representations. |
| **Diagnostics** | `compiler/diagnostics.py` | Infrastructure | Aggregates errors, warnings, source coordinates, and remediation hints. |
| **Domain Specification** | `compiler/language_spec.py` | Infrastructure | Centralized knowledge base of dishes, ingredients, units, and limits. |
| **Scanner** | `compiler/lexer.py` | Phase 1 | Character-by-character scanner emitting strongly-typed tokens. |
| **AST Hierarchy** | `compiler/ast_nodes.py` | Phase 2 | Strongly-typed dataclass nodes representing parsed syntax constructs. |
| **Parser** | `compiler/parser.py` | Phase 2 | Recursive-descent parser enforcing grammar with error recovery. |
| **Symbol Table** | `compiler/symbol_table.py` | Phase 3 | Symbol management, scope tracking, and cumulative quantity records. |
| **Semantic Analyzer** | `compiler/semantic.py` | Phase 3 | Validates culinary rules, compatibility, bounds, and execution sequence. |
| **IR Generator** | `compiler/ir.py` | Phase 4 | Translates validated AST into 3-Address Code (3AC) instructions. |
| **Optimizer** | `compiler/optimizer.py` | Phase 5 | Unit normalization, adjacent instruction merging, dead code pruning. |
| **Code Generator** | `compiler/codegen.py` | Phase 6 | Emits Virtual Kitchen Machine (VKM) assembly code with cycle costs. |
| **Pipeline Service** | `compiler/pipeline.py` | Orchestration | Coordinates compiler lifecycle and generates structured JSON outputs. |
| **Web API** | `app.py` | Presentation | Flask REST server hosting endpoints for IDE interaction and health. |

## 4. Error Handling and Diagnostic Recovery
The compiler implements robust synchronization and error isolation:
1. **Lexical Isolation**: Unrecognized characters are converted into `UNKNOWN` tokens and recorded as diagnostics. Scanning continues without crashing.
2. **Parser Synchronization**: When a syntax error occurs within a statement, the parser reports the exact error and synchronizes to the next `;` or statement-starting keyword (`ADD`, `MIX`, `BOIL`, `SERVE`).
3. **Multi-Error Semantic Reporting**: The semantic analyzer evaluates independent rules (e.g. ingredient compatibility, unit validity, quantity positivity) simultaneously and reports all discovered discrepancies in a single compilation run.
4. **Downstream Gating**: If an upstream phase (Lexer, Parser, or Semantic) registers fatal errors, all dependent downstream phases are safely marked `skipped`, preventing runtime crashes on invalid syntax trees.

## 5. Virtual Kitchen Machine (VKM) Target Architecture
The generated target assembly targets an automated culinary robot consisting of:
- **Mounting System**: Holds preparation vessels (`LOAD_VESSEL`).
- **Dispenser Feeder Network**: Calibrated micro-metering feeders for liquids, powders, and solid pieces (`DISPENSE`).
- **Mechanical Agitator**: Variable-RPM motor for mixing and whisking (`STIR`).
- **Thermal Induction & Convection Subsystem**: Regulated induction burners and convection heaters (`HEAT_BOIL`, `HEAT_BAKE`, `HEAT_FRY`, `HEAT_SIMMER`).
- **Refrigerated Cooling Churn**: Solid-state Peltier chill stations (`COOL_CHILL`).
- **Discharge Plating Station**: Pneumatic arm transferring culinary output to serving plates (`PLATING_SERVE`).
- **Execution Terminator**: Safe power-down of all thermal and mechanical actuators (`HALT`).
